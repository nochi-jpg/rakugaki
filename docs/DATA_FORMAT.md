# データの形（QR・PNG）　形式1

作り方・読み方は `js/codec.js`（QRの中身）と `js/png.js`（PNG）。席と関節の位置は `js/data.js`。

**これから項目は「うしろに足す」だけ**（順番を変えない・消さない）。変えたら形式番号を上げる。
PNGの席（`seat`）とパーツの順番も、あとから変えない。

## QRの共通ルール

- Byte モード・誤り訂正 L。モンスターは約70〜110バイト。
- 数＝可変長の整数（7ビットずつ。続きがあれば最上位ビット1）／文字＝UTF-8の長さ（数）＋本体／ID＝4バイト
- さいごの4バイトはチェック用の数字（FNV-1a 32bit。「カギ＋中身＋カギ」から作る）。合わないQRは読まない。
  カギはコードの中にあるので、くわしい人なら作れてしまう（サーバーがないので防げない）。

## モンスター（種類1）

| 順 | 項目 | 形 |
|---|---|---|
| 1 | 目印 `R` `G`、形式番号（1）、種類（1） | 4バイト |
| 2 | キャラID | ID |
| 3 | なまえ | 文字 |
| 4 | 体形（0=スライム 1=よつあし 2=とり 3=さかな 4=えきたい 5=ロボット 6=にそく）、むき（0=みぎ 1=ひだり） | 1バイト×2 |
| 5 | 描いてあるパーツ（`data.js` の parts の順のビット） | 数 |
| 6 | 色の割合・5教科（国語・算数・社会・理科・英語。千分率） | 数×5 |
| 7 | 色の割合・4教科（こくご・さんすう・せいかつ1・せいかつ2） | 数×4 |
| 8 | つなぐ位置と重なり順（親のあるパーツを parts の順に。x+32、y+32、0=奥 1=手前） | 3バイト×こ数 |
| 9 | モーション番号 | 1バイト |
| 10 | 装備宝石（0=なし） | 1バイト×3 |
| 11 | 生みの親のなまえ、プレイヤーID | 文字、ID |
| 12 | 学年、作った日（2020-01-01からの日数） | 1バイト、数 |
| 13 | じゆうパーツ（スライム）：こ数、（わく番号1〜4・しゅるい・つける位置x・y・0=奥 1=手前）×こ数。ない古いQRは「なし」として読む | 1バイト、（1バイト・1バイト・数・数・1バイト）×こ数 |
| 14 | チェック用の数字 | 4バイト |

## プレイヤー（種類2）

目印・形式・種類（2）→ なまえ → プレイヤーID → 学年 → コイン → 宝石の数と番号 → 解禁した体形（ビット）→ キャラ枠の数 → 日付 → きょうのモードA回数 → モードBで使った教科（ビット）→ ログインボーナス済み → チュートリアル済み → チェック用の数字

## モンスターPNG（1280×720・透過）

- パーツは体形ごとの決まった席に、そのままの大きさで置く。わく（#FF00FF・2px）は席の外がわ。
- 関節のめじるし（#00FFFF）は、わくの外がわに小さな線で描く（絵には重ねない）。
- QRは右下（1056,496 から一辺208の席）。白いふち4マスつき。
- 「くみたてたすがた」（場所は体形ごと）と下のなまえは見るためのもので、データとしては使わない。
- 読みこみ：大きさが同じ・わくの色がぴったり・透明がある → そのまま切り出す（元どおり）。
  それ以外（JPEG・縮小など）→ QRの位置でずれを直す → 半分の解像度で読む → 背景を透明にもどす → 色をパレットによせる（「すこし ぼやけて よみこんだよ」）。
